## 执行中的具体裁定

| 裁定 | 原因及代价 |
|---|---|
| 聚焦的 repository 接口定义在对应应用服务旁 | 计划未规定所有存储方法；未来接口可按需求补方法。 |
| 使用独立 clone 作为工作区 | 原环境没有共享 checkout；代价是额外磁盘。 |
| keycheck、ntfy 使用保留的 secret ID | 全局秘密与账户凭据同样加密；未来命名变化需要迁移。 |
| Batch 增加 Alias 和 More | 通知需显示账户别名，分页需立即继续；只影响内部适配器。 |
| 运行配置从账户阶段移到 CLI 阶段 | 配置实际被启动流程消费；验证在交付前完成。 |
| 设备授权先写内存 staging cache，再验证身份 | 防止误登录替换正确缓存；首次需用主登录邮箱地址，邮箱别名可能被拒绝。 |
| 接受 MSAL 标准 OIDC 身份 scope | 稳定身份验证需要 SDK 账户元数据；同意界面可能显示基础资料权限。 |
| 本地 Unix listener 仅对内核 EPERM 跳过，Docker 检查仅在未显式设置测试镜像时跳过 | 受开发环境限制；实际 Linux CLI、容器验证必须由 CI 提供。 |
| x/text 升至 v0.41.0 | 清除两项未调用路径的依赖漏洞记录；MIME/中文测试验证兼容性。 |
| Go 最低版本升至 1.27.2 | CI 的 1.27.0 标准库有九项调用路径漏洞，1.27.2 已修复；旧编译器需更新。 |
| 生命周期使用工作线程停止屏障 | 阻止旧游标跨过 remove/resync；将来管理 API 也必须经此流程。 |
| OAuth 增加原子 SaveAuthorization | 与移除账户协调，拒绝孤立缓存；存储接口增加一个专用操作。 |
| 增加 schema v2 和每次领取 token | 阻止旧发送结果覆盖新结果；存在小型数据库迁移。 |
| CI 使用 PR/main/版本标签及手动触发 | 避免 feature push 和 PR 重复构建；尚未开 PR 的分支可以手动运行。 |
| 补齐存储 degraded 状态和结构化日志 | 最后对照设计时发现运行诊断未覆盖；日志仅账户 ID、错误类别、耗时和事件数，log_level 可配置，不记录上游原始错误或通知内容。 |
| PR 作为计划内的交付方式 | 用户已批准逐项实现及计划中的 feature PR；保留分支，未自动合并或发布。 |

## 设计缺口补齐

在用户要求继续补充后，补齐以下五项：

- status 的逐账户待发统计，与全局数量在同一事务快照读取；包含没有状态记录的账户。
- SIGTERM 时立即释放每个发送工作线程持有的租约，校验领取 token；崩溃仍使用租约到期恢复。
- StatusService、OutboxService、NotificationService 使用领域 DTO 和仓储接口。本地控制层只解码、调用服务和编码，不依赖 SQLite 或 ntfy 实现；未来 Web UI 可调用同一组服务。
- outbox list 的游标分页、账户及状态筛选。默认 100 条、最大 1000 条，超过 1000 个任务也能连续浏览；输出由数组改为 items/next_cursor 对象。此版本尚未正式发布，调整记录在运行文档中。
- Graph 邮件请求解析 Retry-After HTTP 日期，并与 OAuth 刷新共享解析逻辑。

分页选择任务 ID 的 keyset 游标，避免偏移分页在删除任务后跳过记录；它不提供冻结数据快照，实时变更后可以从首屏重新查询。通知配置保存和解除 blocked 队列沿用已有语义。

本次独立审查发现取消信号落在结果写入期间时可能漏释放租约，以及调度检查退出可能未等待发送清理。分别用两个完成写入取消测试及阻塞清理测试先复现，再修复：所有未完成领取的退出路径统一释放，Supervisor 的所有退出路径都等待发送器结束。

这些补充不新增公开 HTTP 管理端点，也不更改邮箱读取权限或获取正文。
